# 旧后台核心配置核查

核查日期：2026-11-10。以当前 Chrome 中已登录的旧管理系统为准，检查相关页面和新增表单，结合此前核对的系统常规配置 138 个配置键，并对照旧桌面、旧 Web 和新项目源码。本次新增独立 admin 管理模块及新桌面/插件读取链路，不修改原 `super-power-browser-server`。

| 旧配置/页面 | 实际用途与新项目情况 | 本次处理 |
| --- | --- | --- |
| 系统常规配置 `timezone_list` | 旧店铺时区；新项目 `BrowserConfiguration.client/applyDefaults` 已从共享配置表读取 | 保留时区、语言、尺寸和默认值的完整管理，独立服务承接原接口 |
| 平台管理、站点管理 | 旧站点树供店铺选择；新 `PlatformCatalog` 已读取 `platform_site` | 保留分类、平台、站点、网址、启停和排序，保留原 ID |
| 域名走本地网络、`local_resource` | 当前新增表单为规则类型、纯域名；新代理已有 PAC 域名分流 | 新增“域名分流”的直连域名，开店时读取全局缺省；非空设备专属配置优先 |
| 域名加速设置、`static_resource` | 当前表单为加速类型、全局/指定范围、域名；新项目已有专用资源代理 | 新增资源/CDN 域名规则，缺少专用资源代理时明确报错；不搬旧 UID/IP 条件与供应商线路 |
| `switch_cdn`、资源代理池 | 旧固定 CDN 重写域名和供应商节点凭据 | 不迁移旧商业依赖 |
| 黑白名单管理5.1、新防火墙设置5.0、专属白名单、旧防火墙 | 当前黑白名单表单为规则类型、域名；新扩展 DNR 已执行店铺访问规则 | 新增“访问策略”，管理黑白名单与 HTTPS 例外前缀；店铺非空专属规则优先，不迁企业审批及旧 UID 条件 |
| `ipCheckList`、`dynamicIpCheckList`、`check_env_ip_list` | 页面确认 IP 检测列表配置，新桌面已支持检测地址列表及多地址检查 | 新增“IP 检测”，管理代理/本机检测地址和顺序；接入开店、代理检查及本地 IP 检测 |
| `passkey_urls`、`passkey_register_urls` | 旧设置键和插件调用链已核对；新插件用 Chrome scripting matches 注册登录/注册脚本 | 新增“Passkey 规则”，注入全局缺省列表；非空店铺专属规则优先，停用保持原内置规则 |
| 网络延时检测设置 | 检测链接、延时、间隔、消息推送地址；是旧后台监控通知 | 新项目没有对应监控/通知服务，不迁移 |
| `platform_network_site` | 旧数字站点 ID 的测速映射；新桌面使用店铺入口检测 | 不照搬旧映射 |
| `chromium_list_v5`、客户端更新 | 旧内核清单与包；新项目已有内核数据库、对象存储及专用发布 CLI | 保留原发布系统，不改成任意字典编辑 |
| 插件管理、网站/书签管理 | 旧商城、推广、评分、展示、UID可见性；新第三方插件市场未接入 | 本轮不迁移 |
| CSP、Cookie细则、自动填充兼容、语音列表 | 依赖旧定制内核或专项兼容流程 | 不作为本轮独立后台核心配置 |
| 短信、审核、支付、返佣、营销、私有化配置 | 旧业务与运营流程 | 不迁移 |

主要证据（路径相对各仓库）：

- 旧 `rux-browser-master-web/src/utils/mall.ts`：防火墙、站点与特殊内核配置。
- 旧 `rux-browser-master/src/main/zhanfubrowser/RuxToSbp.js`：防火墙/白名单写入原生配置；`DownKernal/DownAndCheckFile.js`：内核清单。
- 旧 `rux-browser-master/Plugin/RXMallHelper.zip` 内 `background/service-worker.js`：资源代理、直连名单和旧 CDN 重写。
- 新 `super-power-browser-server/core/.../config/BrowserConfiguration.java`、`environment/PlatformCatalog.java`：现有五组配置实际读取。
- 新 `DeviceService/ProxyOptions`、桌面 `NetworkInfo`、插件 `proxy-routing.mjs/access-policy.mjs`：现有店铺/设备专属能力及其全局配置接入缺口。

旧后台仅作只读核查；没有修改旧后台数据，也没有导入旧客户记录或供应商凭据。四个新增模块默认停用，运营维护并启用发布后，配置了 `operationsUrl` 的新客户端在下次开店/检测读取；已打开窗口保持原配置。

独立运营服务写入现有共享表，版本冲突和审计与原服务兼容。新增 `GET /api/runtime/config` 使用共享客户会话鉴权；新增配置不经原业务服务下发，不改其代码、迁移和发版方式。桌面与插件新增的消费链独立构建。
