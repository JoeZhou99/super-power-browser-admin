# 新后台业务迁移一期

本期把旧站斧后台中最可能影响 SuperPower Browser 上线运营的业务入口先迁移为新后台只读页面：

| 新页面 | 旧后台/旧前台来源 | 当前状态 |
| --- | --- | --- |
| 用户与成员 | 旧后台 `/auth/members`、旧前台 `company/member/show` | 已接入新后台 `/api/admin/members` 只读契约 |
| 订单与收支 | 旧后台 `/auth/finance/expenditure-details`、旧前台 `money/buyRecord/show/detail` | 已接入新后台 `/api/admin/orders` 只读契约 |
| AI 技能商店 | 旧版 `zhifu/skillStore/*`、`model/skills/*` | 已接入新后台 `/api/admin/skills` 只读契约 |
| 客户代理 | 旧版 `agentIp/showV2`、旧后台 `agent-ip-devices` | 原有 `客户代理` 页面继续使用 `/api/admin/customer-proxies` |

## 旧字段到新字段

- 成员保留账户、用户名、手机号、角色、状态、权限 JSON 和创建时间。旧版的禁用、改密、店铺授权、角色保存需要业务服务完成账户权限校验后再开放写操作。
- 订单保留订单号、业务类型、订单状态、支付状态、履约状态、币种、订单金额、应付金额、过期时间和账户。旧版收支明细中的充值、退款、扣款统计应由账本/订单服务提供汇总，不能由前端重新计算。
- 技能保留名称、版本、分类、平台、来源、作者、作用域、审核状态、审核原因、文件摘要、启用状态和下载次数。新 AI 前端只允许使用审核通过且启用的版本。

## 接口与数据边界

运营服务只读访问业务数据库，不创建或迁移这些业务表。需要先让业务服务完成新表和旧数据映射：`users/account_members/accounts`、`orders/order_items`、`skill_catalog`。表尚未存在时接口返回 `integrationRequired=true` 和明确提示，页面不会展示伪造数据，也不会回退直连旧后台。

本期没有开放支付、取消订单、退款、成员禁用、改密、店铺授权、技能上传、审核、上下架和租户绑定。这些动作需要幂等键、权限校验、审计和业务服务事务完成后再开放。

## 上线顺序

1. 先完成账户/成员和设备、环境的 ID 映射，再开放成员与客户代理读取。
2. 接入订单、订单项、支付尝试和账本后开放订单与收支统计。
3. 建立技能目录、技能版本、审核记录和租户绑定后，切换新版 AI 技能商店来源。
4. 通过跨账户访问、审计和导出权限测试后，再增加写操作。
