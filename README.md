# SuperPower 运营配置后台

管理页面和独立服务放在同一个项目中，目录结构与 `super-power-browser-official` 一致，分别构建和发版。

| 项目 | 说明 | 默认地址 |
| --- | --- | --- |
| [super-power-browser-admin-web](super-power-browser-admin-web/README.md) | Vue 3 + Element Plus 运营管理页面 | http://127.0.0.1:3200 |
| [super-power-browser-admin-server](super-power-browser-admin-server/README.md) | 独立 Java 运营配置服务 | http://127.0.0.1:18082 |

运营服务与 `super-power-browser-server` **共用数据库**，不依赖其源码或 Maven 模块，两端独立构建和发布。管理页面的 `/api/admin/**` 请求指向本项目独立服务。共享数据库结构由业务服务迁移，需要先完成 V27；运营服务只读验证共享结构及业务 Flyway 的 V27 成功记录，不运行迁移。V26 支持 SS 节点，V27 修复 H2 更换迁移连接池后节点写入失败的问题。

## 当前配置范围

首期业务迁移页面已加入“用户与成员”“订单与收支”和“AI 技能商店”。三页先以只读方式接入新后台契约，旧字段映射和业务表前置条件见 [后台业务迁移一期](docs/后台业务迁移一期.md)。

保留原有时区、浏览器语言、窗口尺寸、环境默认值、平台站点，新增旧后台对应的四个核心模块，共九组配置：

| 新模块 | 对应旧后台 | 使用方式 |
| --- | --- | --- |
| 域名分流 | 域名走本地网络、域名加速设置 | 直连、资源代理和 CDN 域名；下次开店读取 |
| 访问策略 | 黑白名单管理、防火墙配置 | 网站黑白名单及 HTTPS 例外前缀；下次开店读取 |
| IP 检测 | 系统常规配置中的 IP 检测地址 | 分别维护代理、本机检测地址；下次检测读取 |
| Passkey 规则 | 系统常规配置中的登录/注册网址匹配 | 维护已有 Passkey 功能适用页面；下次开店读取 |

四组规则支持新增、编辑、删除、组级启停、版本冲突检查与审计。新组初始停用，已打开的窗口不热更新。中继池店铺不应用域名分流，保持所有请求经过绑定出口；非池店铺缺少资源代理时，资源/CDN 使用主出口。增加 Passkey 网址不会自动增加平台支持。

“代理管理”下设客户代理、中继池、中继分组三页。客户代理只读展示客户添加的出口、绑定店铺、最近检测和候选中继，点击 IP 查看详情；不提供客户凭据编辑、删除或运营手动切线。中继池平铺节点，中继分组维护名称、编码、备注、节点、启停及企业授权。客户无需选择线路组，桌面自动选路；已打开店铺可测速、手动锁定或恢复自动，保持原出口。

中继节点支持 HTTP、HTTPS、SOCKS5 和 SS。前三种要求账号密码，SS 使用实际加密方式和密码。页面与普通读取接口不返回密码，编辑时不填写密码表示保留原值。管理保存带版本检查及脱敏审计；停用代替物理删除。用户连接和店铺启动时由业务后端重新校验企业授权。候选按启用状态和顺序选取，尚无基于全网负载的调度或远程 VPS 自动部署。

企业授权目前限制应用内配置读取，已下发的共享节点凭据和运行中的店铺快照不会立即失效。需要网关级即时撤销时，应另行部署企业独立凭据或短期令牌及网关限额。切换上游可能中断长连接，不承诺无感切换。

旧 UID/IP 客户条件、供应商凭据、固定 CDN 重写、营销和财务配置不导入。逐项核查依据见 [旧后台配置核查](docs/旧后台配置核查.md)。

## 客户端读取新配置

更新桌面端和插件构建后，在客户端 `runtime.config.json` 中配置 `operationsUrl` 为此独立服务的地址，或设置环境变量 `SPB_OPERATIONS_URL`。本机可使用 `http://127.0.0.1:18082`，生产使用已部署的 HTTPS 域名；不配置时保留原客户端行为。

客户端携带原客户登录会话请求 `GET /api/runtime/config`，独立服务只读校验共享数据库的 `auth_session/app_user`。客户账号没有管理权限，运营账号也不能代替客户调用该接口。发布、会话撤销和停用均通过共享库生效，无需修改原业务服务。配置服务不可达时，已配置此服务的客户端会提示错误，避免静默跳过策略。

## 启动

先更新业务服务并完成 V27 数据迁移，再启动运营服务。复制 `super-power-browser-admin-server/.env.example` 为 `.env`，配置同一个 MySQL 数据库的 `DB_URL/DB_USER/DB_PASSWORD`，以及与业务服务相同的 `APP_DATA_KEY`，按服务端说明填写首次运营账号。中继密码由运营服务加密，业务服务解密下发；密钥不一致会导致连接失败。

```powershell
# 在服务端目录
cd super-power-browser-admin-server
mvn package
# 本机仅安装 JDK 17 时：mvn '-Djava.version=17' package
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

另一个终端启动页面：

```powershell
cd super-power-browser-admin-web
npm ci
npm run dev
# 构建产物：npm run build
```

也可在构建页面后，从项目根目录运行 `./start-preview.ps1` 启动前端预览；该命令不启动或修改原业务服务。

默认运营 API 使用 `18082`，避开官网注册服务的 `18081`。生产分别发布前端 `dist` 和独立服务 JAR，使用 [Nginx 示例](super-power-browser-admin-web/deploy/nginx.conf.example) 将运营接口代理到新服务。不要把新管理页面继续代理到原业务 API。

服务启动只读检查共享表，不建库、不运行或修改原 Flyway 历史。配置初始化只补缺失组，不覆盖既有配置、站点和运营密码。共享数据库的表结构仍由原业务项目负责。

本机旧预览若使用独占模式 H2 文件，不能直接让第二个 JVM 打开同一文件；可为两服务配置同一 MySQL/H2 TCP 数据源进行联调。此项目不会修改原预览脚本、复制真实数据库或重启原进程。
